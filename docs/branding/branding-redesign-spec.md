## 1. 이 문서의 역할

이 문서는 최종 Brand_Combined_Mockup.html을
기존 서비스에 안전하게 적용하기 위한 실행 명세다.

목업에 이미 포함된 내용을 다시 설계하거나 중복 추가하지 않는다.

HTML은 목표 화면의 배치·문구·색상·정보 순서를 보여준다.
이 MD는 적용 범위·보호 대상·작업 단계·검증 기준을 정한다.

기존 예약·달력·관리·공유·홍보·인증 기능은 그대로 유지한다.

### 이번 작업이 아닌 것

- 기존 앱 전체 재개발
- 세부 업무 화면 전체 리디자인
- 새로운 달력·예약·공유·홍보 기능 개발
- 기술 스택 변경
- 대규모 리팩터링
- 자동 운영 배포

## 7. 화면 2 적용 기준

### 목업 위치

#guide-screen

이 화면은 세로로 읽는 서비스 이야기·안내 화면이다.
한 화면 높이에 모든 내용을 넣지 않는다.

### 7.1 상단 이동

- 브랜드 화면으로 돌아가기
- .section-links의 여섯 개 섹션 바로가기

최종 목업의 구성 순서를 유지한다.

### 7.2 #why — 왜 만들었는가

핵심 제목:

사무장이 없거나, 고령화로
체험 운영이 어려운 마을이 있었다.

인터뷰에서 확인한 다음 상황을 설명한다.

- 체험 운영과 예약 관리의 어려움
- 종이·전화 관리의 누락과 변경 전달
- 홍보 문구 작성 부담

‘적은 인력’ 중심의 이전 설명으로 되돌리지 않는다.

인터뷰 수·날짜·직접 인용은 제공된 근거 없이 만들지 않는다.

### 7.3 #direction — 어떤 방향을 검토했는가

제목:

익숙한 카카오로 운영을 도울 수 있을까?

목업의 검토 과정과 세 가지 기준을 유지한다.

- 익숙한 접점에서 시작
- 입력보다 메뉴 선택
- 필요한 업무를 연결

카카오 선택을 현장 문제와 연결한다.
다른 대안과 비교 실험했다는 근거 없는 설명은 추가하지 않는다.

### 7.4 #response — 무엇을 구현했는가

다음 세 대응 카드를 유지한다.

1. 예약과 관리
2. 정보와 공유
3. AI 홍보 지원

각 카드는 다음 순서를 따른다.

현장에서 확인한 상황
→ 운영 지원 방향 검토
→ 구현한 대응

위 영역은 이미 목업에 있으므로 중복 생성하지 않는다.

예약·관리는 연결된 웹과 기존 달력을 이용하는 흐름으로 설명한다.
AI는 사진 기반 홍보 초안 지원의 역할을 명확히 보여준다.

공유 대상·방법·권한은 실제 코드와 사용자 확인을 따른다.
자동 알림이나 실시간 동기화를 근거 없이 설명하지 않는다.

### 7.5 #roles — 누가 사용하는가

목업의 두 역할 안내를 유지한다.

- 체험객
- 사무장·운영 담당자

실제 역할과 권한을 조사한다.
목업의 명칭에 맞춰 새로운 권한이나 계정을 만들지 않는다.

체험객·사무장이 같은 달력·데이터·권한을 쓴다고 단정하지 않는다.

### 7.6 #usage — 어떻게 사용하는가

제목:

문장을 외우기보다, 메뉴를 누른다.

예약·관리:
말풍선 메뉴 선택 → 연결된 화면 이용 → 기존 달력·예약 확인

홍보:
홍보 메뉴 접근 → 사진 올리기 → AI 초안 확인

실제 구현에 단계 차이가 있으면 먼저 보고한다.
목업에 맞추려고 기존 업무 흐름을 수정하지 않는다.

### 7.7 .validation-note — 구현과 효과 구분

인터뷰로 확인한 문제, 구현한 대응,
추가 확인이 필요한 현장 효과를 구분한다.

이 영역은 신뢰를 위한 본문이다.
개발자용 안내로 오인해 일괄 삭제하지 않는다.

### 7.8 #start — 이용·시연 안내

- 제공된 카카오 채널 연결
- 확인된 기존 시연 경로 연결

시연 URL을 추측하지 않는다.
목적지가 확인되지 않으면 공개 링크 적용을 보류한다.

## 13. 접근성과 검색 설명

### 접근성

- 의미 있는 제목 계층
- 활성 화면의 명확한 제목
- 이동에는 링크 사용
- 키보드 포커스 표시
- 숨긴 화면으로 포커스가 이동하지 않음
- 이미지 대체 텍스트
- 새 창 안내
- 주요 CTA의 충분한 조작 영역
- 200% 확대와 좁은 화면 확인
- 가로 스크롤과 잘림 방지

모션을 추가하지 않는 것을 기본으로 한다.
스크롤 모션을 사용하면 reduced-motion을 존중한다.

### 메타데이터

목업의 ‘브랜드 목업’ title을 공개 화면에 사용하지 않는다.
실제 브랜드와 화면 목적을 반영한 title·description을 적용한다.

검색과 공유를 위해 두 화면을 별도 URL로 제공할 필요가 있는지
현재 라우팅과 렌더링 방식을 조사해 제안한다.

단순 해시 전환만으로 두 화면의 검색 노출이 보장된다고 설명하지 않는다.

메타데이터를 위해 새 라이브러리를 설치하지 않는다.
실제 URL 확인 전 canonical·공유 URL을 임의 작성하지 않는다.

## 15. 기능 분류
