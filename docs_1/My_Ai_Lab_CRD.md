# 체험마을 AI사무장 - 계정 및 API 키 관리대장

## 0. 문서 목적

여러 외부 서비스(공공데이터, TourAPI, LLM 3종, Supabase, Vercel, 카카오)의 계정과 인증키를 한곳에서 추적 관리하기 위한 문서다. 실제 키 값은 이 문서에 절대 기록하지 않으며, 어디서 발급받았는지·어떤 이름의 환경변수에 매핑되는지·한도가 어떤지만 관리한다.

주의: 이 문서 자체를 GitHub 공개 저장소에 커밋해도 되지만, 실제 키 값이 담긴 .env 파일은 반드시 .gitignore에 포함하고 절대 커밋하지 않는다.

## 2. API 키 및 환경변수 매핑표

| 환경변수명 | 발급처 | 용도 | 무료 한도(확인 필요 항목은 실제 신청 화면에서 재확인) | 만료/갱신 정책 |
|---|---|---|---|---|
| PUBLIC_DATA_SERVICE_KEY | 공공데이터포털 | 「전국농어촌체험휴양마을표준데이터」 OpenAPI 호출 | 일반적으로 일 트래픽 한도 있음(신청 화면에서 확인) | 활용기간 만료 시 재신청 필요할 수 있음 |
| TOUR_API_SERVICE_KEY | 공공데이터포털(한국관광공사 TourAPI) | 주변 관광정보 조회 | 위와 동일 포털이므로 유사한 한도 구조 | 위와 동일 |
| GEMINI_API_KEY | Google AI Studio | 기본 LLM(추천/감성분석/문구생성) | 무료 티어 존재, 모델별 상이 | 키 자체는 만료 없음(수동 폐기 전까지) |
| CLAUDE_API_KEY | Anthropic Console | 보조 LLM(품질 우선 시 전환용) | 결제 등록 후 종량제 | 키 자체는 만료 없음 |
| OPENAI_API_KEY | OpenAI Platform | 보조 LLM(선택) | 결제 등록 후 종량제 | 키 자체는 만료 없음 |
| SUPABASE_URL | Supabase 프로젝트 설정 | 데이터베이스 접속 주소 | 프로젝트당 1개 고정 | 프로젝트 삭제 전까지 유지 |
| SUPABASE_SERVICE_ROLE_KEY | Supabase 프로젝트 설정 | 서버 사이드 전용 DB 접근키(관리자 권한) | - | 필요 시 재발급 가능(재발급 시 기존 키 무효화) |
| KAKAO_REST_API_KEY | 카카오 디벨로퍼스 | 카카오 로그인/기타 REST 기능(필요 시) | - | 이번 카카오 연동에서 필요하면 신청 |
| KAKAO_ADMIN_KEY | 카카오 디벨로퍼스 | 관리자 권한 API(주의해서 사용) | - | 이번 카카오 연동에서 필요하면 신청 |
| KAKAO_EVENT_API_URL / 관련 인증정보 | 카카오 i 오픈빌더 / 비즈니스 도구 | 이벤트 API(선톡) 발송 | 건당 소액 과금(무료한도 없음) | 이번 단계 성공 후 신청. 이번 단계에서는 쓰지 않는다 |
| CRON_SECRET | 직접 생성(임의의 긴 문자열) | Vercel Cron이 호출하는 동기화 엔드포인트 보호용 | 해당 없음(자체 발급 값) | 유출 의심 시 즉시 변경 |

## 3. 발급 절차 체크리스트

### 3-1. 공공데이터포털 (농촌체험마을 표준데이터)

1. data.go.kr 로그인
2. 「전국농어촌체험휴양마을표준데이터」 검색
3. 오픈API 탭에서 활용신청
4. 마이페이지 > 오픈API > 활용신청 현황에서 서비스키(인코딩/디코딩) 확인
5. 본 관리대장의 PUBLIC_DATA_SERVICE_KEY 행에 발급 완료 여부만 기록(값은 .env에만 저장)

### 3-2. 한국관광공사 TourAPI

1. 위와 동일한 공공데이터포털 계정에서 「한국관광공사_국문 관광정보 서비스」 검색
2. 활용신청 및 서비스키 발급
3. TOUR_API_SERVICE_KEY로 저장

### 3-3. Gemini API

1. Google AI Studio 접속 및 로그인
2. API 키 발급 메뉴에서 신규 키 생성
3. GEMINI_API_KEY로 저장
4. 무료 티어 한도(요청수/분, 토큰수 등)를 발급 화면에서 확인해 이 문서 2장 표에 추가 기록

### 3-4. Claude API

1. Anthropic Console 접속 및 로그인
2. 결제 수단 등록(선불 크레딧 방식일 수 있음)
3. API 키 발급
4. CLAUDE_API_KEY로 저장

### 3-5. Supabase 신규 프로젝트

1. Supabase 대시보드 로그인
2. 기존 활성 프로젝트 개수 확인(무료 한도 2개)
3. 여유가 있으면 신규 프로젝트 생성, 없으면 기존 미사용 프로젝트를 Pause 처리 후 생성
4. 프로젝트 설정에서 SUPABASE_URL과 SUPABASE_SERVICE_ROLE_KEY 확인

### 3-6. Vercel 신규 프로젝트

1. Vercel 대시보드 로그인
2. GitHub 저장소와 연동하여 신규 프로젝트 생성
3. 프로젝트 설정의 Environment Variables 메뉴에 본 문서 2장의 모든 환경변수를 등록

### 3-7. 카카오 관련

이번 카카오 연동:

1. 카카오톡 채널 관리자센터에서 채널 개설(개인/일반)
2. 카카오 i 오픈빌더 챗봇 관리자센터 가입 및 봇 생성 신청(신청 사유 구체적으로 작성)
3. 승인 완료 후 스킬 URL 등록

이번 단계가 완료되고 성공한 다음:

4. 비즈니스 도구에서 개인 비즈월렛 생성 및 결제수단 등록
5. 이벤트 API로 선톡을 구현한다. 이번 단계의 예약 확인은 `예약 현황`과 `내 예약` 조회다

## 4. 보안 원칙

1. 실제 키 값은 이 문서에 절대 기록하지 않는다
2. .env 파일은 로컬에만 존재하며 .gitignore에 반드시 포함한다
3. Vercel 배포용 환경변수는 Vercel 프로젝트 설정 화면에서만 등록한다
4. 키가 외부에 노출된 것으로 의심되면 즉시 해당 서비스 콘솔에서 재발급(Rotate)하고 이전 키를 폐기한다
5. Supabase의 service role key는 강력한 권한을 가지므로 프론트엔드 코드나 공개 저장소에 절대 포함하지 않는다
